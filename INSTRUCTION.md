# CampusOS — Local Development Setup

## Prerequisites

- Docker + Docker Compose (for Evolution API)
- Node.js >= 20
- npm
- WhatsApp installed on your phone (for QR scanning)

## Quick Start

### 1. Start Evolution API

Create `docker-compose.yml` at the project root:

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: evolution
      POSTGRES_USER: evolution
      POSTGRES_PASSWORD: evolution
    ports:
      - "5433:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

  evolution-api:
    image: atendai/evolution-api:latest
    ports:
      - "8080:8080"
    environment:
      AUTHENTICATION_API_KEY: 429683C4C977415CAAFCCE10F7D57E11
      DATABASE_PROVIDER: postgresql
      DATABASE_CONNECTION_URI: postgresql://evolution:evolution@postgres:5432/evolution
      CACHE_LOCAL_ENABLED: "true"
      CACHE_REDIS_ENABLED: "false"
      LOG_LEVEL: info
      LOG_BAILEYS: error
    depends_on:
      - postgres

volumes:
  pgdata:
```

Run:

```bash
docker compose up -d
curl http://localhost:8080/   # verify it's running
```

### 2. Start Next.js

```bash
npm run dev
```

Open http://localhost:3000

## Testing Announcements

1. Open http://localhost:3000/announcements
2. Login (create account with email + password, min 12 chars)
3. Click **Check Server** — confirms Next.js API is alive
4. Click **Create Instance** — creates a "primary" WhatsApp instance on Evolution API
5. Click **Get QR Code** — Evolution API returns QR; scan with WhatsApp → Linked Devices → Link a Device
6. Wait for status to show "Connected"
7. Select audience (Unpaid Parents / All Parents), compose message, click **Send**

## How It Works

- The Announcements page at `/announcements` sends all WhatsApp API calls to `/api/whatsapp/*`
- Next.js API routes (`app/api/whatsapp/`) proxy these requests to Evolution API at `EVOLUTION_API_URL` (default: `http://localhost:8080`)
- Evolution API manages the persistent WhatsApp WebSocket connection using Baileys
- Auth state (QR session) persists in Evolution API's PostgreSQL database

## Troubleshooting

| Symptom | Fix |
|---|---|
| `docker compose up` fails on port 8080 | Another service is using port 8080. Change the host port (e.g. `"8081:8080"`) and update `EVOLUTION_API_URL` in `.env` |
| Phone can't connect to scan QR | Your phone needs network access to the machine running Docker. On same WiFi, use your LAN IP instead of localhost in the QR URL (not configurable — the QR is generated by Evolution API on the same host) |
| "Instance creation failed" | Check `docker compose logs evolution-api` — likely DB connection issue |
| QR not appearing | Evolution API may need a moment after instance creation. Click "Get QR Code" again |
| Messages not sending | Verify connection state is "Connected". If it shows "Disconnected", click "Get QR Code" to reconnect |
| Docker Evolution API can't reach Postgres | Ensure Postgres container is healthy: `docker compose ps` — both should show "Up" |

## Architecture

```
Phone (WhatsApp) ←WebSocket→ Evolution API (Docker) ←HTTP→ Next.js (localhost:3000) ←Browser→ User
                                    ↓
                            PostgreSQL (Docker)
```

The user never talks to Evolution API directly — all calls go through Next.js API routes which proxy to Evolution API.
